**Repair calls:** additional corrective LLM requests after the initial response. A batched request counts once, including unsuccessful repairs. `0` means repair handling was enabled but no corrective request was made; `—` means repairs were disabled or repair metadata is unavailable. Subtotals and totals are `—` if any included requirement is untracked. Token and cost totals include recorded repair calls. API/network retries are excluded.

**Defined:** consistent tests whose satisfying instances are unique modulo atom renaming under the declarations and the command's original scopes and integer bitwidth. A complete concrete encoding certifies uniqueness directly; otherwise the first solution is encoded as a complete instance predicate I and Alloy checks whether the original test P admits a solution satisfying P and not I. All user-declared signatures and fields, including ordering successors, are compared; private module implementation relations and Skolem witnesses are excluded. The target requirement is not imposed during this check, so negative scenarios remain satisfiable. Tests with non-isomorphic satisfying instances are excluded from later validity, completeness, and coverage checks.

**Valid %:** 100 × valid tests / requested tests (2 × n per requirement). Subtotals and totals divide summed valid counts by summed requested counts. Missing tests therefore reduce this percentage; `Tests` still counts actual generated tests. `—` means a requested count is unavailable, including in any containing subtotal or total.

**Maximum coverage:** reference [results.json](/Users/alcino/Projectos/Alloy-LLM-Testing/results/fac27/maxcover/results.json), scope **4** per top-level domain. `n` is the requested number of tests per classification. `Complete ≤4` requires exactly n positive and n negative tests, all valid, with every possible instance of each test using at most 4 atoms per top-level domain under the declarations and earlier requirements. Actual populations are checked, rather than the command's declared upper bounds. `% of max` is 100 × detected wrong specifications / maximum detectable for the same n. Equivalent specification rewrites are accepted; model, oracle, cumulative requirements, and specification totals are cross-checked when the saved dataset is available. Skipped sizes use an earlier certified 100% result. Subtotals sum maximum counts and report the unweighted mean of per-suite percentages over complete suites within the reference scope. An unavailable comparison makes that subtotal unavailable. `—` denotes an ineligible suite, missing optimum, incompatible totals, or an undefined percentage when the optimum is zero.
